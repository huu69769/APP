# 发布设置（第一次需要手动做一次）

push 到 `main` 分支后，GitHub Actions 会自动：

1. 构建**网页版**，发布到 GitHub Pages：`https://huu69769.github.io/APP/`
2. 构建 **APK**，上传到 GitHub Releases：`https://github.com/huu69769/APP/releases`

要让它跑起来，需要你在 GitHub 网页上做下面几步。每一步只需要做**一次**。

---

## 第 1 步：打开 GitHub Pages

1. 打开仓库页面 → 上方 **Settings**（设置）
2. 左边栏点 **Pages**
3. **Build and deployment → Source** 选 **GitHub Actions**

> GitHub Pages 免费版要求仓库是**公开**的（Public）。

---

## 第 2 步：生成签名密钥（keystore）

> ⚠️ **非常重要**：这个密钥文件以后**每次**构建都要用同一个。
> 如果密钥丢了或者换了，新版 APK 就**无法覆盖安装**，只能卸载旧版再装新版，**手机里的数据会全部丢失**。
> 所以生成之后，请把 `release.keystore` 和密码**另外备份**（比如存到 U 盘和网盘各一份）。
> **不要**把它放进这个仓库里（仓库是公开的，任何人都能看到）。

### 2.1 准备 keytool 工具

`keytool` 是 Java 自带的小工具。

- 如果电脑上装过 Android Studio，它自带 Java，不用另外安装。
- 否则去 <https://adoptium.net/> 下载安装 **Temurin JDK 17**（一路点「下一步」即可）。

装好后打开终端确认一下：

- **Windows**：按 `Win` 键，搜索「PowerShell」并打开
- **Mac**：打开「终端」（Terminal）

输入：

```
keytool -help
```

如果显示了一堆说明文字，就说明可以用了。
（Windows 上如果提示找不到命令，而你装的是 Android Studio，把下面命令里的 `keytool` 换成
`"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe"`。）

### 2.2 生成密钥

在终端里先进入一个你记得住的文件夹（例如桌面），然后运行：

```
keytool -genkeypair -v -storetype PKCS12 -keystore release.keystore -alias worklog -keyalg RSA -keysize 2048 -validity 10000
```

它会依次问你：

1. **输入密钥库口令**：自己设一个密码（输入时屏幕上不显示字，是正常的），再输一遍确认。
   **把这个密码记下来。**
2. 名字、组织、城市等问题：可以随便填，也可以直接按回车跳过。
3. 最后问「是否正确？」：输入 `y`（中文系统可能要输入 `是`）然后回车。

完成后，文件夹里会多一个 `release.keystore` 文件。

### 2.3 把密钥转成 base64 文本

GitHub Secrets 只能存文字，所以要把密钥文件转成一长串文字：

- **Windows（PowerShell）**：
  ```
  [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\release.keystore")) | Out-File -Encoding ascii keystore-base64.txt
  ```
- **Mac**：
  ```
  base64 -i release.keystore -o keystore-base64.txt
  ```

然后用记事本 / 文本编辑打开 `keystore-base64.txt`，里面是一长串字母和数字。

---

## 第 3 步：在 GitHub 上设置 Secrets

1. 仓库页面 → **Settings** → 左边栏 **Secrets and variables** → **Actions**
2. 点绿色按钮 **New repository secret**，一共添加 **4 个**：

| Name（名字，要一字不差） | Secret（值） |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `keystore-base64.txt` 里的**全部**内容 |
| `ANDROID_KEYSTORE_PASSWORD` | 第 2.2 步设的密码 |
| `ANDROID_KEY_ALIAS` | `worklog` |
| `ANDROID_KEY_PASSWORD` | 和 `ANDROID_KEYSTORE_PASSWORD` **一样**的密码 |

3. 添加完以后，**删掉**电脑上的 `keystore-base64.txt`（`release.keystore` 本身要留着备份）。

> Secrets 是加密保存的，只有 Actions 运行时能用，别人看不到，你自己以后也看不到内容（只能覆盖）。
> 所以 `release.keystore` 文件和密码一定要自己另外备份好。

---

## 第 4 步：触发一次构建

push（或合并）代码到 `main` 分支就会自动开始。也可以手动触发：

仓库页面 → **Actions** → 左边选 **Release** → 右边 **Run workflow**。

大约 15–25 分钟后：

- 网页版：打开 `https://huu69769.github.io/APP/`
- APK：打开 `https://github.com/huu69769/APP/releases`，最上面那个版本里下载 `.apk` 文件

如果某一步失败，Actions 页面里会显示红叉，点进去能看到原因。
比如没设置 Secrets 时，会显示「缺少签名 Secrets」。

---

## 在手机上安装 APK

1. 用手机浏览器打开 Releases 页面，下载最新的 `.apk`
2. 打开下载的文件。第一次安装时，手机会提示「禁止安装未知来源应用」，
   按提示允许**浏览器**安装应用即可
3. 以后有新版本，同样下载安装，会**直接覆盖**旧版，数据保留

## 怎么确认密钥没变？

每次构建的 Actions 日志里，「Verify signature」这一步会打印一行 `SHA-256 digest`。
这串字符每次都应该一模一样。
